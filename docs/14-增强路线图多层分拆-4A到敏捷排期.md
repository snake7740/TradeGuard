### 0.1 A0 角色边界强制（隐患修复 · 已实施）

**隐患识别**：角色分化的三层落地状况核查——

| 层 | 状况 | 证据 |
| --- | --- | --- |
| 数据库层 | ✅ 真实分化 | 02-roles.sql：tg_web/tg_app 读写矩阵、只增表 REVOKE |
| 前端页面层 | ⚠️ 纸面边界 | role.js/router.js 菜单与路由守卫仅展示过滤，绕过前端直达 API 即失效 |
| API 网关层 | ❌ 缺失（修复前） | api_guards.py 仅有全局 Bearer；X-Operator 仅审计记录，不校验角色权限 |

**修复设计**（api_guards.py 端点级 RBAC，对齐 03 §6 权限矩阵 × 01 §6 角色旅程）：

| 端点 | 允许角色 | 对齐依据 |
| --- | --- | --- |
| `/api/cases/*/review` | 风控审批官 | 人工复核唯一出口（02 §7 human_only） |
| `/api/approvals/*/decide`、`/api/config*` | 审批官 ∪ 策略管理员 | tg_web 的 approval_record/sys_config UPDATE 授权 |
| `/api/kb/applications/*/publish\|reject` | 策略管理员 | DA-INV-06 知识发布仅限人工且归策略线 |

**行为契约**：已知角色越权 → 403 `E-FORBIDDEN-ROLE` + `api.forbidden` 留痕；agent: 自声明穿透至端点 human_only 守卫 → 409 `E-HUMAN-ONLY`（语义分层：403=角色无权，409=业务门拒绝，与 07-case-actor-gate 对齐）；未识别调用方（历史测试名/MCP/CI）放行 + `api.unknown_actor` 留痕，收敛节奏与 R-37 一致。契约测试：test_multi_role_flow 流程 E（SC-18）。

**四角色 × 四专属工作台分化**（与 API 门控同源对齐，消除「共享工作台、按钮级差异」的归属错乱）：案件工作台归值班员专属（立案 → 信号聚合 → 调查取证 → 提请处置，复核 UI 整体剥离迁出）；复核审批工作台归审批官专属（`ApprovalPortal.vue` 重写为人工复核队列默认 tab + 审批工单双 tab，复核弹窗与 submitReview 自案件工作台迁入）；审计工作台归审计员专属（审计回放 + 结果核验）；策略工作台归策略管理员专属（知识审核发布）；可观测面板为唯一共享页。`router.js` meta.roles 白名单 + `App.vue` menus roles + HOME_BY_ROLE 三层同步，角色切换统一回各自首页。四角色菜单自此真实分化：值班员=案件工作台+可观测；审批官=复核审批工作台+可观测；审计员=审计工作台+可观测；策略管理员=策略工作台+可观测。

**端到端验证证据**（浏览器四角色接力，CASE-20260819-a60cd2 主线）：值班员受理告警立案 → 值班员越权调 review 复测 403（修复前实证 200）→ 审批官复核确认（`case.transition.ReviewConfirmed` actor=human:风控审批官）→ 审批官批准冻结（approver=human:风控审批官 → DispositionExecuted → DISPOSED）→ 审计员触发结果核验（VerificationPassed → ARCHIVED，复盘自动提入库申请 pending）→ 策略管理员审核发布复盘（reviewer=human:风控策略管理员 → published，DA-INV-06）。全量回归 252 过。
