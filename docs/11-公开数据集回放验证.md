# 11 · 公开数据集回放验证（行业效度，诚实标注）

> **这是什么 / 给谁看**：用公开欺诈检测数据集回放 AA-SK-01 确定性内核，
> 验证骨架对真实行业数据分布的效度。面向**评审者 / 后端开发者**。
> 事实源与全部数字：[docs/reports/dataset-replay.md](reports/dataset-replay.md)（脚本自动生成，可复现）。

## 1. 为什么做（证据链定位）

本项目「场景效度」此前有两块证据：自造数据的 110 例测试（正确性）与
device-guard 第二场景（骨架复用性，[docs/10](10-场景扩展映射-device-guard.md)）。
第三块缺口是**行业真实分布**——自造数据天然"配合"规则，公开数据集不配合，
能暴露规则在真实分布下的真实表现。这就是本回放要补的证据。

## 2. 回放设计要点（方法学）

| 要素 | 选择 | 理由 |
| --- | --- | --- |
| 数据集 | ULB creditcard（Zenodo DOI 10.5281/zenodo.7395559，md5 校验通过） | 公开可获取、无需凭据、欺诈标签明确、284,807 笔全量回放 |
| 调用方式 | **内核直调**（`score_signals`/`velocity_bonus`/`triage`，原权重原阈值） | 证明被验证的是骨架本身而非某个适配层；全链路已由 110 例测试覆盖 |
| 无标签泄漏 | Class 仅用于事后对照 | 评分输入只有 Amount 与 Time |
| 对照基线 | 随机告警（precision=欺诈率）+ 固定金额阈值 + **正常笔落入突破簇比例** | 没有对照的命中率都是假命中（见 §3 B 组） |

## 3. 结果与诚实解读

**强项（有效证据）**：

- 骨架**可消费公开数据集**：284,807 笔全量、~5,000 簇聚类、PR 扫描，全程内核
  原参数直调，管线无一处因真实分布的数据形态（金额重尾、时间高密度）崩溃；
- 业务指标**可解释可复核**：告警队列规模（BR-01 工作点 3,560 笔）、
  precision/recall、PR-AUC 与基线对照全部落盘，一条命令复现。

**负结果（如实披露，同样是有价值的结论）**：

- **A 组（金额维度）**：AP 0.0021 仅为随机基线的 1.2 倍——金额单维在该数据集
  接近无效。原因可解释：ULB 欺诈以小额 card-testing 为主（欺诈金额中位 9.25
  < 正常 22.00），金额天然不判别。这从反面支持本项目"多源加权聚合"的设计：
  单维弱信号不能独立成案，必须多源叠加（AA-SK-01 的存在理由）；
- **B 组（velocity 维度）**：欺诈落入 BR-14 突破簇 95.7% 看似强命中，但
  **正常笔对照是 99.2%（lift 0.96x）**——假命中。根因是数据集无主体 ID，
  以全市场流近似主体后，94% 的簇都突破"单主体 1h≥10 笔"的阈值，规则退化
  为近恒真。**结论：本数据集不具备验证主体级 velocity 规则的条件**，
  需要带主体标识的数据集（Sparkov/PaySim）才能做真正的主体级验证（后续工作）。

> 方法学教训（已固化在报告模板中）：任何"命中率"类指标必须带同分布对照，
> 否则在高密度数据上极易得出虚假强结论——这正是"诚实标注"的价值所在。
