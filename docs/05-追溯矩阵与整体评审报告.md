## 3. 整体 Review 记录

### 3.1 审查方法

**第一轮（v1.0）**：对全部 6 份文档执行三类核对：①跨文档编号引用一致性（BA/AA/DA/TA 编号双向对账）；②业务域残留检查（保险域术语清除验证）；③赛题原文逐条覆盖核对（§2）。

**第二轮（v1.1，DDD/BDD/TDD 注入后）**：在第一轮基础上追加四类核对：④DDD 构件一致性（上下文↔Agent↔数据表↔聚合四层对账）；⑤领域事件目录与 02 §7 状态机、RocketMQ 事件流的一致性；⑥BDD 场景对 BA 规则与 6 条 DA 不变量的覆盖完备性；⑦业务闭环五阶段是否均有场景承载（结果见 §1.1，全部覆盖）。

**第三轮（全团队多角色评审：产品经理/行业架构师/后端架构师/前端架构师/DBA/DevOps 逐角色对照赛题提纲）**：发现 6 处新问题（R-07～R-12，见 §3.2），全部当场修复；重点覆盖业务规则分段完备性、部署拓扑自洽性、资源估算、并发控制与前端界面缺口。

**第四轮（演示可行性专项：必选技术栈核对 + 页面演示三端真实调用链审计）**：发现 1 处新问题（R-13），当场修复；确认必选项零缺漏、演示链路非写死 mock。

**第五轮（交付体系注入：07 敏捷拆分与 OpenAPI 3.0 契约 + 08 数据字典）**：执行四类核对：⑧openapi.yaml 可解析性（YAML 解析通过：15 paths / 30 schemas）；⑨API-W 编号与 Story 引用对账（发现并修复 5 处编号错位）；⑩枚举字典三方一致性（08 §2 ↔ openapi CaseStatus/SseEvent ↔ 03 §9.2 事件目录，12 状态/10 事件全同）；⑪MCP 工具清单一致性（02 §5 的 6+3 工具 ↔ 07 API-M-01~09 ↔ openapi x-mcp-tool，全同）。本轮无遗留问题。

**第六轮（关联性审计 + 社区对标）**：全文档编号反向引用扫描，发现 4 个孤岛模块 + 1 个悬空术语（R-14～R-18），全部当场修复；同步检索社区同领域项目（AWS 官方反欺诈参考架构、GNN 反欺诈、多 Agent 金融系统、Agent 观测平台、合成金融数据）形成 [09 社区对标分析](./09-社区对标分析.md)，结论：主链路与行业参考架构同构，审批门控+审计链为差异化优势，行动项已回接 07 排期。

**第七轮（对标借鉴整合 + 全文档一致性同步）**：将 09 三项行动项整合入文档体系，按"规则→场景→字段→契约→故事"五环贯通：①新增 BA-BR-14（velocity 频次特征强制规则，13→14 条）；②新增 SC-11 验收场景（10→11 个，验收线 11/11）；③DA-T-04 新增 velocity_json 字段（03 §4 + 08 字段字典 + openapi RiskSignal Schema 三方同步，YAML 解析实测通过：15 paths / 30 schemas / velocity_json 在场）；④AA-SK-01 职责补 velocity 计算；⑤04 §8 合成数据发生器补 PaySim 分布参数；⑥US-E3-03 升 6 点并挂 SC-11、US-E7-03/05 验收标准更新（Story 总数 29 不变）；⑦00 计数与版本号同步（v1.4）；⑧09 行动项状态全部置为已整合。本轮无遗留问题。

**第八轮（Sprint 0 技术体系落地实测 + 实现反哺文档）**：仓库骨架与全栈部署一次性落地并逐项取证：①docker compose 10 容器全 Up（postgres/namesrv/broker/nacos/web-api 五个 healthcheck 全 healthy）；②`/api/health` 返回 UP 且 POST `/api/alerts` 立案落库（CASE-20260812-42f022，US-E1-01 验收达成）；③两个 MCP Server streamable-http 握手 200（protocolVersion 2025-03-26）；④合成数据冒烟档入库（500 账户/5261 交易/2 团伙）且 fn_related_graph 2 跳查询实测返回；⑤case-events Topic mqadmin 预建成功；⑥backup.sh 备份演练产出 dump；⑦AgentTeams 官方脚本（WSL2 非交互模式）安装成功，Manager/Matrix/MinIO/内置 Higress 全就绪并已接入 tradeguard-net（US-E1-02 基础设施部分达成，5 Worker 创建待真实 LLM Key 后在控制台完成）。发现并修复 2 处文档与实现偏差（R-19/R-20，见 §3.2）；部署实测坑位（RocketMQ 外挂配置 NPE、Nacos v3 强制 AUTH_TOKEN、mcp SDK 1.2.1 不支持 streamable-http 升 1.9.4、分区表授权）已回写 04 §3 备注与 scripts 文档。US-E1-03（Nacos 注册元数据/阈值热更）为 Sprint 1 事项。**架构设计落地补充（同日）**：三端按设计植入架构构件并取证——后端状态机（12 态/16 事件/18 迁移路径，与 DDL CHECK/openapi 枚举逐字一致）+ 仓储/端口适配器/乐观锁写路径模板，API-W-01~15 全量声明；存储端 04-invariants.sql 状态迁移白名单触发器与知识发布人工门控（双守护实测：非法迁移应用层 409 E-BAD-TRANSITION 与 DB 触发器 RAISE 均拒绝）；MCP 工具全集 API-M-01~09 实测可列（补 API-M-05/06）；前端全量契约声明 + 角色守卫，vite 构建通过；状态机全链冒烟：立案→聚合→调查→复核确认→审批批准（version 0→2）+ 审计链 3 条 + SSE 首帧连通。
