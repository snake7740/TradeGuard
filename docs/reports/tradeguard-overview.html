一、为什么需要 · 1/3

三个痛点，每个都有对策与闭环验证

交易欺诈已从「单笔攻击」演变为「团伙化、工业化」——单交易视角的决策引擎难以应对；每个痛点下方标注本方案的对策与可验证的闭环证据

痛点一：团伙化、工业化欺诈

测卡（Card Testing）、账户盗用（ATO）、跑分洗钱，由同一团伙跨多账户协同——孤立看单笔交易无法识别关联。

对策：关联网络四类关系（同设备 / 同收款方 / 同 IP 段 / 同联系方式）2 跳扩展 + 弱连通分量团伙发现，跨账户关联自动还原。
闭环验证：场景二调查定性「跑分」团伙（P24）· 团伙发现毫秒级（P26）

痛点二：多源信号分散

交易、征信、舆情、投诉散落在各自系统，人工汇总慢且易遗漏，错过处置黄金窗口。

对策：四源信号一次聚合——标准化、降噪合并、velocity 频次特征 + 加权评分，自动产出 0-100 风险分（BA-BR-14）。
闭环验证：低风险响应 0.0 分钟（KPI-01，P20）· 场景一全自动零人工（P23）

痛点三：告警疲劳与处置断链

低风险告警海量导致疲劳；高风险处置缺统一审批与审计闭环，合规与追溯无保障。

对策：风险分级自动分流（低自动 / 中复核 / 高强制审批）+ 12 态状态机 + 处置后核验三态 + 只增不改审计日志。
闭环验证：留痕 100%（KPI-05，P20）· 误报自动回滚（P25）· 未批准冻结不可执行（P24）

价值主张

以 多 Agent 协同替代「人工告警流水线」：低风险事件自动处置、高风险事件证据化调查、全部处置动作合规可追溯——把风控人员从重复劳动中解放出来，聚焦真正需要判断的高风险案件。对策机制详见第三部分（P11-17），闭环数字见第四部分（P18-21），三个场景实证见第五部分（P22-25）。

监管背景：《银行卡业务管理办法》、反电信网络诈骗法规、金融监管总局欺诈风险治理要求03
一、为什么需要 · 2/3

行业现状：三类主流方案的边界

理解现有方案「能做什么、不能做什么」，才能明确本方案补的是什么
方案类型 擅长 局限
规则引擎 / 决策引擎（Drools、Falcon 等） 毫秒级实时决策，确定性好，可解释、可审计 以单交易/单账户为视角，缺乏跨账户关联；规则维护成本随欺诈手法演化持续攀升
图风控（Neo4j、TigerGraph、GNN） 发现团伙关联、识别资金网络，弥补跨账户盲区 强在「发现」，弱在「处置」——识别之后如何自动处置、如何审批、如何核验，仍要另起炉灶
通用 LLM / Agent 方案（LangGraph 等） 自然语言推理、证据链生成，理解力强 输出不确定、幻觉风险；缺乏风控必需的确定性、人机审批边界与审计追溯

结论

三类方案各有所长，但都缺一条：把「发现」到「处置」再到「核验」串成可审计的闭环，并在其中守住「高风险必由人确认」的边界。这正是本方案要补的位置。

一、为什么需要 · 3/3

方案定位：确定性打底，LLM 增强，人守住边界

三条设计主线，逐条回应上一页三类方案的短板

五阶段闭环

不是孤立的「检测」，而是 信号聚合 → 根因定位 → 处置执行 → 核验审计 → 知识沉淀 的完整链路。每一次处置都有核验，每一次误判都回流为知识，系统越用越准。

机制落点：BA-CAP-01~07 按阶段编排能力（P06）· 12 态状态机承载流转（P17）

人机边界清晰

低风险可自动处置，高风险一律由人最终确认。Agent 负责建议与执行低风险动作，账户冻结、大额处置必须经过人工审批——让自动化「敢用、可控」。

机制落点：三通道分流 BA-BR-01/02（P08）· human_only 迁移门（P17）· 接口级角色门控（P10）

确定性优先，LLM 增强

核心评分、状态迁移、处置门禁全部由可复现的规则内核执行；LLM 只做规划、互审、分派等建议性增强且无决策权。即使没有 LLM Key，系统照常闭环运行（规则同构降级），LLM 是「加分项」而非「前提」。

机制落点：规则内核 = 纯函数 + DB 触发器双守护（P09/P17）· LLM 五点全有规则同构降级（P13）

可验证性承诺

设计不停留在纸面：339 例自动化测试（真实数据库 + 双 MCP 实链路）、SC-01~27 BDD 场景矩阵、ULB 公开数据集 284,807 笔回放、六维 KPI 周期落盘——第四部分逐项给出证据。

三主线与后续页的对应：五阶段闭环 → P06 能力地图（BA-CAP-01~07）· 人机边界 → P10 角色与 BA-BR-01/02 强制 · 确定性优先 → P13 五点增强全部规则同构降级05

▼ 风险分级（分流点）按分数进入三条通道，去向与效果如下

低通道　BA-BR-01 · 分 < 40 且 < 5,000 元

自动处置：系统自动放行或拦截，决策依据写审计，全程无人工（免审批单，SC-01）。效果：响应 0.0 分钟（KPI-01），场景一实证零人工（P23）。

中通道　BA-BR-01 · 40–69

转人工复核：值班员判断「放行 / 拦截 / 升级」，系统不做自动处置（SC-10）。效果：审批单与复核结论全留痕（KPI-05 100%）。

高通道　BA-BR-02 · ≥ 70

深度调查 + 强制人工审批：批准才执行（DA-INV-02）；驳回回退人工复核且禁止再入自动通道（BA-BR-07，SC-03）。效果：未批准冻结不可执行（场景二 P24）。

风险阈值可通过配置中心（Nacos）动态调整，无需重启08
