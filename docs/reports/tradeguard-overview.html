01 · POSITIONING

行业定位：发卡/支付机构的交易反欺诈风控

金融风控「交易欺诈风险」子类 ｜ 监管依据：《银行卡业务管理办法》、反电信网络诈骗法规、金融监管总局欺诈风险治理要求

痛点一：团伙化、工业化欺诈

测卡攻击（Card Testing）、账户盗用（ATO）、跑分洗钱——单交易视角的决策引擎无法发现跨账户关联。

痛点二：多源信号分散

交易流水、征信、舆情、投诉分散在不同系统，风控值班员人工归集耗时，错过黄金处置窗口。

痛点三：告警疲劳 + 留痕缺失

低风险告警量大导致疲劳；高风险处置缺乏统一审批与合规留痕。

▼

价值主张：以多 Agent 协同替代「人工告警流水线」

低风险事件自动处置、高风险事件证据化调查、全部处置动作合规留痕——告警响应时效从小时级压缩到分钟级（演示口径实测 KPI-01：低风险案件立案→处置完成 0.0 分钟，达标）。

事件驱动闭环与 12 态状态机（双守护）

规模

12 态 · 18 事件 · 21 迁移，纯函数状态机（app/core/state_machine.py）。扁平信封 {case_id, trace_id, occurred_at, event, actor, payload}。

双守护

应用层状态机 + DB 白名单表触发器（case_state_transition）；写路径事务内 set tg.actor，trg_case_actor_gate 按 actor 前缀拦截——五对人类迁移仅 human:* 可执行。

事件投递语义

进程内总线必达（SSE 实时推送；慢消费者 64 槽上限降级丢弃，不阻塞主链路）+ RocketMQ 尽力而为（case-events 实测连通）+ EventWorker DB 轮询保底（单飞锁防重、失败不重试）——不依赖单一中间件可用性。

核验三分支（AA-SK-04，诚实语义）

执行一致→归档（trace 残缺仅告警绝不回滚）；不一致→反向处置回滚（逆动作对授权）；无凭证/拒回滚→RollbackEscalated 升级人工（不发 RollbackExecuted，语义不撒谎）。实测 D3 全分支通过。
