# TradeGuard 社区对标分析

> 版本：v1.2 ｜ 目的：对照社区同领域高 star 项目、商业头部平台与官方参考架构，校验本方案不闭门造车；每个参考项给出"已对齐 / 待借鉴 / 明确不采纳"结论。检索时间：2026-08（v1.2 行业核实 2026-08-21）。**行动项已于 v1.1 全部整合入文档体系；v1.2 新增 §4 代码实证功能盘点、§5 行业核实数据、§6 五维水准定位、§7 诚实披露，全部对比以当前仓库真实代码为准。**

## 1. 对标结论速览

| 本方案设计 | 社区主流做法 | 结论 |
| --- | --- | --- |
| 信号聚合为纯规则（AA-SK-01） | 规则 + ML velocity 特征双轨 | **已对齐初版定位**（评估重心在 Agent 闭环而非算法）；合成数据集保留 velocity 统计字段，作后续演进空间 |
| 图关联仅 2 跳 SQL/UnifiedModel 查询 | GNN（CARE-GNN/Rio-GNN）端到端反欺诈 | **明确不采纳训练路线**（成本与项目重点不符）；图查询拓扑能力与社区蓝图一致，方向正确 |
| AgentScope Studio + OTel 语义 | Langfuse 等专门 Agent 观测平台 | **已对齐**；若 Studio 评估能力不足，Langfuse 为已声明替换路径（04 §7 替换成本） |
| 场景化合成数据集（US-E7-05） | PaySim / SDV 生成金融交易数据 | **待借鉴**：PaySim 交易类型分布与账户状态机值得参考；本方案不引入 GAN 类生成器，场景化 + 规则采样即可 |
| 事件驱动状态机（RocketMQ + 幂等键） | AWS 参考架构同为 EventBridge + SQS 驱动 | **已对齐** |
| 多 Agent 职能分工 | FinAgent 等多 Agent 金融系统 | **方向有社区先例**；差异点：本方案以审批把关与审计链为核心，社区项目多缺此层 |
| 外部数据源走模拟 MCP（AA-MCP-02） | 百炼 MCP 广场等公开市场直连真实服务 | **明确不采纳（2026-08-14 评估）**：广场无持牌征信/反诈舆情/客服投诉类服务，场景不匹配 + 征信合规边界 + 演示确定性基线；端口/防腐层已使未来真实适配器可零改动接入（详见 [02 §5](./02-应用架构AA.md#aa-mcp-02-外部数据服务-mcp) 评估结论） |
| 规则 + 统计基线评分（代码实证 §4.3） | 商业头部：自适应 ML / 千级特征（Stripe Radar 1000+ 特征、Featurespace 行为自适应） | **算法层属初版定位**（评估重心在 Agent 闭环）；pyod 三统计检测工具已在码但未接线闭环（§4.2 警示），诚实标注见 §7 |

## 4. 代码实证功能盘点（v1.2，对比基线，逐项可在仓库复核）

### 4.1 mcp-core 注册工具 12 个（全部有契约编号）

query_transactions(M-01) / query_related_graph(M-02，2 跳上限 + topology_stats) / query_case_signals(辅助只读，含 velocity_json，非契约项) / execute_disposition(M-03，审批门控 + 幂等) / query_disposition_result(M-04) / submit_kb_application(M-05，pending 人类确认) / query_audit_trail(M-06) / record_case_signals(M-10) / create_approval_request(M-11) / record_case_evidence(M-12，只增) / apply_risk_bonus(M-13，幂等打标) / record_agent_memory(M-14)。

### 4.2 mcp-external 注册工具 7 个 = 契约 4 + pyod 3

- 契约 4：query_credit(M-07，个人征信持牌红线保留 mock) / query_sentiment(M-08) / query_complaint(M-09) / query_enterprise(M-16，五维 + 双轨降级 + degraded 留痕)。
- **警示差异（代码 vs 文档口径）**：pyod_iforest / pyod_lof / pyod_ecod 已注册 @mcp.tool，带 query_reason 强制门禁 + 依赖白名单门（pyod/numpy 未装即 E-TOOL-UNAVAILABLE 拒绝，US-E12/F1，docs/14 §1.4，输出仅建议分不裁决），但**全仓无技能调用方**（planner 四源不含 pyod）、**无 API-M 契约编号**、tests 无闭环覆盖，仅 ecosystem-interop-report.md 提及。属"能力在码、未接入闭环"，**不应计入 16 契约工具口径**；后续接入门槛 = planner 接线 + 契约编号 + SC 场景。

### 4.3 web-api 技能层（真实算法与编排能力）

- aggregation：EWMA 基线 + P95 分位 + baseline_deviation/bonus；fund_loop / rapid_inout / night_burst 三模式匹配；velocity 统计；normalize_credit_report 防腐层翻译。
- investigation：topology_stats（B1 拓扑线索，仅研判不裁决）；match_hypothesis 假设验证；InvestigationService。
- planner：rule_plan + make_plan 双轨（规则/LLM）；execute_plan 四源（征信/舆情/投诉/企业资质）；replan_from_gaps 缺口重规划；reflect 反思双轨；review_disposition 审批把关双轨。
- state_machine：12 态 + 事件驱动 TRANSITIONS，与 01-schema.sql DA-T-03 CHECK 约束逐字对齐。
- 门禁（test_mcp_gate 8 例）：C1 approval_ref 防伪/跨案/反向动作对豁免；C2 回滚门控；C3 处置结果回查。
- 回归基线：30 文件 317 例全绿（v1.5 取证，见 CLAUDE.md）。

## 7. 诚实披露（避免自评幻觉）

1. **无模型训练管线**：无特征工程平台、无模型评估/回滚——明确不采纳（§1），非"落后"。
2. **非毫秒级流式决策引擎**：事件驱动状态机是演示基线定位，无真实 TPS 压测数据，不与 Stripe Radar 级实时引擎对比吞吐。
3. **合成数据规模**：场景化合成数据可支撑验收，不能主张真实欺诈检出率；所有规则/统计能力未经真实流量验证。
4. **外部源以 mock 为主**：仅企业资质具备双轨真实接入能力（且需厂商凭据）；个人征信持牌红线保留 mock 是合规决策。
5. **pyod 三工具属"能力在码未接线"**：对比中不应计入闭环能力（§4.2）。
6. **行业数据口径纪律**：§5 中"官方宣称"数据未经独立第三方审计，引用时须带口径标注。
