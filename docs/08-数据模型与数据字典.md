# 08 · 数据模型与数据字典

> 本文档是 TradeGuard 文档集的**数据契约视角**：[03 DA](./03-数据架构DA.md) 的逻辑模型在本文档展开为字段级数据字典，是 DDL、OpenAPI Schema（[07 §5](./07-敏捷拆分与API契约.md#5-api-目录统一-openapi-30)）与 TDD 测试夹具的共同依据。变更纪律：先改本文档 → 再改 openapi.yaml / DDL → 最后改代码。

---

## 1. 通用约定

| 约定 | 规则 |
| --- | --- |
| 命名 | 表名/字段名全小写 snake_case；主键 `{表名单数}_id`；外键 `{引用表}_id` |
| 时间 | 一律 `timestamptz`（UTC 存储，前端本地化展示） |
| 金额 | `numeric(14,2)`，禁止浮点 |
| 个人标识 | 一律哈希（SHA-256）或后四位，明文不落库（01 §8、03 §7） |
| 主键生成 | 业务主键按规则生成（如 `CASE-yyyyMMdd-序号`），不用自增暴露业务量 |
| 软删除 | 全库不使用软删除；只增表（信号/证据/审计）禁止任何 UPDATE/DELETE |
| 乐观锁 | 可被并发写的状态表带 `version int not null default 0`（DA-INV-01 守护） |

## 5. 领域事件 Payload 字典（case-events Topic）

公共信封（**扁平结构，与 SSE/API-W-14 推送体同一序列化**）：`case_id / trace_id / occurred_at / event / actor / payload`（03 §9.2）。trace_id 取案件立案 trace_id（repositories register/transition 透传，缺失回落 uuid）。事件分四类，共 25 个事件名（与 §2 event_tag、openapi SseEvent 枚举逐字一致）：

| 事件类 | 事件名 | payload 实况 |
| --- | --- | --- |
| 立案事件 | CaseRegistered | `{subject_ref, risk_score}`（repositories.register 发布） |
| 状态机迁移事件（18） | AggregationStarted / SignalsAggregated / NoiseDismissed / InvestigationRequested / InvestigationCompleted / ApprovalApproved / ApprovalRejected / DispositionSubmitted / DispositionExecuted / DispositionFailed / RollbackToReview / VerificationPassed / VerificationFailed / RollbackExecuted / RollbackEscalated / ReviewConfirmed / ReviewDismissed / CaseArchived | 统一 `{from, to}`（repositories.transition 经状态机白名单发布，事件名即迁移事件名） |
| 计时器事件（2） | ApprovalEscalated | `{approval_id, threshold_minutes}`（BA-BR-13 超时扫描，actor=system:timer-BA-BR-13） |
| | VerificationOverdue | `{threshold_minutes}`（BA-BR-08 核验超时扫描） |

业务细节字段（risk_score/exec_id/approval_id 等）以 DA-T-03~07 落库为准，事件信封不重复携带（消费方按 case_id 回查共享状态，AA-CL 闭环语义）。

## 6. 错误码表

| 错误码 | 含义 | 触发点 | 处置 |
| --- | --- | --- | --- |
| E-DISP-AUTH | 处置缺审批凭证触边界 | AA-SK-03 / API-M-03 | 拒绝执行，转审批（SC-02） |
| E-AGG-ALL-FAIL | 全部数据源聚合失败 | AA-SK-01 | 事件转人工 |
| E-CASE-STATE | 非法状态迁移 | 状态机守护 | 拒绝并审计（DA-INV-01） |
| E-IDEMPOTENT-CONFLICT | 幂等键冲突且载荷不一致 | API-M-03 | 返回首次结果 + 告警 |
| E-APPROVAL-DECIDED | 工单已决策重复提交 | API-W-09 | 幂等返回首次决策 |
| E-KB-NOT-PENDING | 文档非 pending 状态操作 | API-W-12/13 | 拒绝（DA-INV-06） |
| E-EVIDENCE-MISSING | 冻结缺证据链 | DA-INV-04 | 拒绝写入（BA-BR-03） |
| E-REASON-REQUIRED | 外部源查询缺事由 | API-M-07/08/09 | 拒绝（BA-BR-10） |

HTTP 映射：业务拒绝类 409，缺参 400，资源不存在 404；响应体统一 `{code, message, trace_id}`（openapi.yaml Error Schema）。

## 7. 与 OpenAPI Schema 的对照纪律

- 每个 REST 响应 Schema 字段必须能溯源到本文档某表字段或派生字段（如 approval 的 escalated_at 直接落 DA-T-07，由 BA-BR-13 计时器写入）；
- 新增字段三处同改：本文档 → openapi.yaml → DDL/迁移脚本；
- CI 检查：openapi.yaml 与本文档表名/枚举值一致性脚本（US-E7-01 DoD 项）。
